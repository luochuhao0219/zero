# 昨晚遗留项补做记录

日期：2026-11-08（Asia/Shanghai）。这是 `ACCEPTANCE-2026-11-08.md` 的后续记录，旧样本、旧录屏保留，不改写历史结果。

## 本轮实际修改

1. **降档响应**：原来 1 FPS 时每一档要等约 20 秒。严重卡顿现在按至少四个慢帧、累计两秒的窗口触发，仍逐档、最多四档，不因单次停顿就降级；暂停清空观测窗口。
2. **真正释放昂贵渲染路径**：第一档释放 MSAA 双缓冲；第二档禁用 bloom/阴影；第三档释放后处理及 bloom 目标，改为直接渲染。仅关闭 bloom 无法解决软件着色瓶颈，因此进一步将戏台物理材质一次性替换成 Lambert 顶点照明；保留几何、色彩贴图、透明裁切、自发光动画及操作坐标，取消低档法线/金属/清漆效果。标准档不变。
3. **稳定场景合成**：校园/内厅/灯市稳定段走单纹理合成，穿门与影幕仍使用原三纹理空间转场；展馆仍直接绘制。
4. **输入所有权**：第一根指针拥有拖动；第二指不能改成环绕、移动已有拖动或提前释放交互锁。取消操作释放 capture、清定时器，不提交一次新操作；打开弹窗、标签页隐藏也取消抓取。
5. **后台与 reduced-motion**：隐藏标签页取消尚未触发的自动通关，前台再判断；暂停原因仍独立。reduced-motion 游戏静止时不再每个 rAF 重绘，真实输入与视角/布局变更仍唤起绘制。
6. **诊断与复现**：提供真实绘制计数/实际绘制 FPS、后处理状态、资源数与画质首尾档位，避免把空闲 rAF 或仍在降档的样本误称稳态。

## 性能：同一软件渲染器的前后对照

环境：Linux HeadlessChrome 156、ANGLE Vulkan SwiftShader、1440×900、DPR=1。单个自动化会话，无录屏；每份采样约 12 秒。以下是本轮改前/改后，不拿昨晚可能不同负载的 8～10 FPS 展馆样本当严格 A/B。

| 场景 | 本轮改前平均 FPS / P95 | 最终平均 FPS / P95 | 解释 |
|---|---|---|---|
| 校园 | 25.51 / 50ms | 27.30 / 50ms | 都包含 passage 0→2 降档，非稳态 |
| 内厅 | 53.02 / 33.3ms | 60.00 / 16.7ms | passage 第四档稳态 |
| 展馆往返滚动 | 59.42 / 16.7ms | 59.25 / 16.7ms | 改前已接近 60；没有把它说成此次数倍提升 |
| 戏台进入后 | 0.99 / 1116.5ms | 5.14 / 233.3ms | 改前 stage 0→1，改后 3→4，不直接当同档提升倍数 |
| **戏台第四档稳态** | **1.77 / 583.3ms** | **5.15 / 200ms** | 同 stageTier=4、DPR=.7；低档材质策略不同，实际绘制 5.23 FPS，约 2.9 倍提升 |

只去掉后处理的中间实验为 **1.91 FPS / P95 566.7ms**，不足以解决问题，故未在这里仓促收工。该阶段证据单独放在 `after-post-only/` 和 `stage-after-post-only-settled.json`。

改前实际戏台 trace 中 GPU 任务累计约 10.78 秒，rAF 回调累计约 0.51 秒，支持优先降低着色工作量，而不是只优化 JS 循环。`trace-summary.json` 保存聚合；这些事件跨线程、可能嵌套，不能相加视为整页耗时。大体积原始 trace 未纳入仓库。

**仍未达到任务书实体 GPU ≥55 FPS、P95 ≤25ms / 真手机 ≥30 FPS 的目标。** 软件渲染改善不是实体设备性能验收；校园当前样本也仍有降档与长帧。不能把“自动降档有效”说成“全程丝滑”。最终低档实拍见 `qa/followup/final/stage-low-quality.png`，牺牲高级表面效果，但保留三维戏台和操作对象。

## 补测与证据

### 普通动态三关与结束路径

- 不启用 reduced-motion；前两关使用真实键盘，第三关真实鼠标拖动两手杆与人物间距。三关均达到 100 分，完成记录为 `[0,1,2]`。
- 第三关后反复执行“通关框 → 留影册 → 关闭 → 恢复通关框”三次，再结束游戏并返回公共内厅；未丢失通关状态，路线转场锁已解除。
- 证据：`qa/followup/game/level-{1,2,3}.json`、`collection-return.json`、`ending.json`、`normal-third-completed.png`；浏览器错误列表为空。截图已人工目视复核。

### 输入取消、后台与减少动态效果

- 真实鼠标拥有拖动，再向 canvas 合成第二根指针的 down/move/cancel：游戏状态不变，第二指没有抢占或结束第一指；释放真实 capture 并发送下一次原生指针事件后，拖动/指针计数均清零。不是实体双指触控测试。
- 真正新开另一标签并切回，隐藏约四秒：stage 与 passage 绘制计数均没有增长，游戏时间也没有推进；没有伪造 `document.hidden`。
- reduced-motion 游戏空闲 1.5 秒，stage 绘制计数保持 `84 → 84`；随后真实键盘操作能更新状态并重新绘制。
- 证据：`qa/followup/stability/{pointer-cancellation,visibility,reduced-idle}.json`。单元测试另覆盖探索把手的跨物件/跨指针所有权、取消后的滚动恢复、取消清掉尚未触发的 wheel 提交。

### 循环与资源稳定性

- **20/20 轮通过，循环段共 836.647 秒（约 13 分 57 秒）**。独立核对 `cycle-01.json` 至 `cycle-20.json` 的文件数、内部序号、资源数与 summary 一致，不只依赖脚本最后一行 PASS。
