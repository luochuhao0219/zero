# 0.9 连续双路线：实施与验收记录

日期：2026-11-08（Asia/Shanghai）。基准：仓库内《连续动画与双路线改版任务书 V1.0》。

## 结论与边界

功能改版已经落到源码：公共校园开场停在三维内厅、双门明确选择、五段连续可逆历史馆、场景内拖动实验与排戏、接回原三关及原路返回。未更换技术栈，未引入新运行依赖，原存储键保留。

**这不等于任务书的全部硬件验收已经通过。** 当前机器使用 SwiftShader 软件 WebGL，没有可用的 NVIDIA 驱动；没有约定实体桌面测试机，也没有实体手机/触屏。本记录仅证明实际执行过的浏览器操作与该环境下的性能，不将移动视口模拟等同于实体触屏，不将软件渲染帧率等同于目标硬件帧率。桌面平均 ≥55 FPS / P95 ≤25ms、移动降级 ≥30 FPS 仍需在约定设备复验。

## 实测环境与方法

- Linux x86_64，HeadlessChrome 156.0.0.0；桌面 1440×900、设备 DPR 1。
- WebGL renderer：ANGLE / Vulkan / SwiftShader Device (Subzero)。
- 静态服务：`python3 server.py --port 4173`。
- 浏览器统一由 agent-browser 驱动；真实 click / mouse / press 操作。eval 仅用于读取诊断、读取布局与存储、原生页面滚动及 rAF 采样，不注入通关状态。
- 性能使用 `scripts/qa/sample-performance.js`，每样本约 12 秒、真实 rAF 帧间隔；记录平均、P95、分辨率、画质与 draw 次数。采样时停止录屏，只保留一个自动浏览器会话。rAF 调度不等于 GPU 时间；reduced-motion 静止时更不能拿 rAF 数量当实际渲染帧率。
- `docs/qa/baseline/` 为前期并发会话、未降级版本诊断，**不是最终成绩，也不能用来严格量化优化幅度**。

## 最终单会话软件渲染样本

每段约 12 秒，1440×900、系统 DPR 1、正常动态；原始数据见 `docs/qa/desktop-*.json`。这些是本机实测，不是目标设备达标成绩。

| 场景 | 平均 rAF FPS | P95 帧间隔 | 开场/戏台画质档（开始→结束） |
|---|---:|---:|---|
| 校园 | 8.62 | 116.7ms | 1/0 → 4/0 |
| 内厅 | 10.74 | 100.1ms | 4/0 → 4/0 |
| 展馆往返滚动 | 10.36 | 116.6ms | 4/0 → 4/0 |

**本机软件渲染未达到任务书性能指标**，尤其三维戏台开销较大；游戏样本结束时才降至第一档，不代表最低画质的稳定性能。不能从这里推算实体 GPU / 手机帧率。自动降档已触发，采样记录无资产错误，浏览器错误列表为空。硬件复验和进一步性能优化仍是交付限制。

### 移动视口与存档复验

- 393×852 竖屏内厅双门、编戏侧栏与真实收票；保存七次后作品数为 6。
- 刷新后草稿标题“双路线回归草稿”、两演员参数、六张作品及三关 completed=[0,1,2] 均保持，reduced-motion 保持启用。

- 自动化初次点击屏外侧栏按钮没有触发；补上 `scrollintoview` 后真实点击保存成功，无需修改应用逻辑。仅为视口/鼠标模拟，不冒充实体触摸验证。

### 下载工具限制

agent-browser 此版本的录屏上下文会取消 CLI 下载，页面无对应 JS 错误；正常非录屏上下文已成功下载 WebP。录屏中仍实际点击下载按钮，但不把录屏上下文的取消伪称成功，也没有为了迁就录屏工具更改页面下载实现。

## 交付材料

- `recordings/museum-route.webm`：校园→内厅→历史馆五段、拖动与收票、逆向返回、馆末连接通道→灯市→内厅。

- `scripts/qa/record-{museum,game}.sh`：可复现实操，`browser-common.sh` 为原生滚动/真实拖动/批量真实按键辅助。
- `docs/DUAL-ROUTE.md`：路线、镜头表、交互、原存储键、素材复用与画质策略。
- `screenshots/museum-*.png` / `screenshots/game-*.png`：辅助截图，不代替两条完整录屏。
